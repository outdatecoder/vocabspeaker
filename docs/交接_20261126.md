## 8. 经验教训（按事故讲，不按条文讲）

### 8.1 用实现自己的公式验证它 → 永远绿
`tracks_from_gaps()` 用同一个下标公式核对输出，得到 "56/56 吻合"，实际 46 条错位。
改用**独立内容特征**（真词边界必须是长静音）立刻暴露。**规则 R1：验证必须独立于实现。**

### 8.2 只看日志前 12 行就下结论
`Select-Object -First 12` 只看了追踪开头，就断言"HTTP 与 file:// 表现一致"，
真正证据在后段暂停恢复阶段。**规则 R2：断言必须落在被验证的那一段上。**

### 8.3 靠推断恢复被压缩的信息
`GAP_EC == GAP_WORD == 0.5` 无法区分，却靠"奇数下标"赌静音奇偶性，内部停顿一多就翻转。
正解是改数据结构：**一词一个 MP3**，歧义从结构上消失，播放器还净减几十行。**规则 R3。**

### 8.4 只断言"有反应"不断言"反应对了"
旧探针只查按钮文字变"暂停"，而 bug 表象恰是"按钮说暂停、音频静音"——
**11 PASS / 0 FAIL 却漏掉 2 个真 bug**。观测点要选副作用（`play/pause` 调用序列、实际 `src`、内部 `idx`）。**规则 R4。**

### 8.5 明知测不出却不做用例
"Edge 在 seek 期间返回新值、Safari 返回旧值，所以我测不出"——只写进文档，
下一轮用户报"没解决"，又在 Edge 上验证、又没抓到。**规则 R5：环境差异要变成可执行用例，不许只留注释。**

### 8.6 `typeof` 存在 ≠ 能用
`typeof showSaveFilePicker === 'function'` 在 `file://`（opaque origin）下也为 true，
只有调用才抛 `SecurityError`，于是下载提示**错误承诺**"文件夹可以自己选"。**规则 R6：能力检测放到调用点的 try/catch。**

### 8.7 自己交付的诊断工具自己没跑
调试浮层只设 `className` 没设 `id`，而取值用 `getElementById` → 误判"`d` 键没反应"，
还去怀疑用户的键盘环境。**规则 R7。**

### 8.8 `.bat` 的 `goto` 指向 `::label`（2026-11-20 事故）
`::` 在 cmd 里是**注释**，`goto start` 找不到 `:start` → `The system cannot find the batch label specified - start`，
窗口一闪，用户报"双击没反应"。`start_pet.bat` 里六个标签全中，**换哪台机器都起不来服务**，
而 AGENTS.md 一直把 `cmd /c start_pet.bat --no-browser` 当常用命令 —— 从没真跑通过。
修：标签改单冒号；失败分支补 `if /i not "%~1"=="--no-browser" pause`。

### 8.9 便携包的隔离模式会把脚本目录踢出 `sys.path`
`pythonXY._pth` 一旦存在，`sys.path` 只来自该文件，**脚本自身目录不再自动加入**，
于是 `serve.py` 的 `import webgen` 在交付包里报 `ModuleNotFoundError`，而自检（只验第三方库能导入）全绿。
修：`serve.py` 在 `import webgen` 前把自己的目录插进 `sys.path`。
另：`._pth` 里**不要写 `import site`**，否则用户机器的 `%APPDATA%\Python\...\site-packages` 又会被挂上来。
自检现在逐条校验 `sys.path` 每一项都在 `runtime\` 内，并真跑 `serve.py --help`。

### 8.10 Windows 内置 `tar.exe` 打 zip 会毁掉中文文件名
`tar -a -c -f x.zip <dir>` 把中文名按 CP437 重编码，`PET主题词汇` 变成 `\u2553\u2248\u2560…`，
466 个条目全毁，解压后目录名不可还原（会以为"打包成功"）。
改用 Python `zipfile`（非 ASCII 名自动带 UTF-8 标志 `0x800`）。
**验证时不要用 `tar -tf` 判断**——GBK 控制台下两种状态都显示乱码，分不清是显示问题还是数据坏了。

### 8.11 Word 的 `Range.Information(3)` 是**段尾页**
一条词条的中文末行溢到下一页时整条被记成下一页（`232 grandpa` 因此被归到第 5 页）。
正解：`_word_pages.ps1` 把 range collapse 到段首再取页，段尾页另存 `page_end`。
另：逐段取页号 0.21s/段 → 2191 段要 8 分钟（假死）；改成 `Content.Text` 取一次 + 每页 `GoTo` 一次，39 页 19s。
**先读 `Content.Text` 再 `GoTo`**（顺序反了 43.8s vs 18.8s）。
