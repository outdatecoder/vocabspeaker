## 1. 一句话范围

四个功能都属于**词库工作台（`/`）与生成器（`/generator`）这条工具链**，**都不改词库包的结构**（`index.html` + `pack_data.json` + `audio/` 的形态不变），因此都不破坏"双击 `index.html` 就能离线播放"这个前提。

| # | 功能 | 一句话 | 用户能感知的收益 |
|---|---|---|---|
| A | 打包下载 zip | 工作台卡片上多一个「⬇ 打包下载」，把整个词库打成一个 `.zip` | 发给别人/拷到平板时**不会丢 `audio/` 子目录** |
| B | 校对表「插一行」 | 校对时能在某一页/组中间补一行 | 解析漏词不用整页重来（也是 OCR 的前置） |
| C | OCR（jpg / 扫描件） | 上传照片也能抽词条（**RapidOCR，模型随包自带、离线**） | 手头只有纸质书照片时不用先转 docx；代价是便携包约 **+170~200 MB** |
| D | 重复页检测 | 并入前提示「这一页像是已经进过包」 | 避免同一页并两次；不用等 409 才发现 |

## 3. 目标与非目标

### 3.1 目标

1. 用户能把一个词库以**单个文件**交给别人（微信/邮件/网盘），对方解压双击 `index.html` 就能听。
2. 用户能在校对表里补上解析漏掉的词条，不必整页重解析。
3. 用户能直接上传**手机拍的词汇表照片**并得到可校对的词条。
4. 用户在并入前就能看到"这页可能已经在包里了"，而不是被 409 拦在半路。

### 3.2 非目标（本期明确不做）

| 不做 | 原因 |
|---|---|
| 改词库包结构（加 lang/voice/索引） | 会破坏"包是纯静态、双击即用"，且工作台 §9.4 已定为本期不做 |
| 云端 OCR / 联网识别 | 与"离线、不上传"前提冲突；且会引入隐私问题 |
| 多图一次上传成一份文档 | 会动 job 模型（`doc_id` 一文档一文件）。v1 用"一张图一个 doc + 并入"代替 |
| OCR 手写体 / 竖排 | 识别率不可控，明确不支持并在 UI 说明 |
| 页级重复的**强制阻断** | 用户可能故意重并去"更新"某页；页级只做**提示 + 二次确认**，硬拦仍由词级 `_dup_report` 负责 |
| 打包下载的断点续传 / Range | 单文件十几 MB，一次下发即可 |
| 工作台内嵌播放 | 工作台 §11 已明确不做 |

## 4. 功能 A · 打包下载 zip

### 4.1 用户故事

> 我把《初中英语词汇表》做好了，要发给孩子平板。微信不收文件夹，网盘传文件夹会把 `audio/` 弄丢。我希望点一下得到一个 `.zip`，对方解压双击 `index.html` 就能背。

### 4.2 交互

| 位置 | 行为 |
|---|---|
| 工作台卡片操作区 | 在「打开播放器」与「＋ 继续加词表」之间插入第三个链接：`⬇ 打包下载`（`<a download href="/api/export?pack=…">`） |
| PC / 移动端 | **两端都渲染**。移动端正是主要场景（下载到平板/手机） |
| 点击后 | 浏览器原生下载；文件名 = `<词库名>.zip`（中文名，RFC 5987 编码） |
| 下载中 | 按钮就地变成「打包中…」并禁用，完成/失败后恢复（`<a>` 禁用用 `aria-disabled` + 拦点击，不用 `pointer-events` 假禁用） |
| 词库包内页面 | **不出现这个入口**（包内没有服务端，出现就是假承诺，R6） |
| 失败 | 就地 toast 显示服务端 `error` 原文，不猜原因 |

### 4.3 接口契约

```
GET /api/export?pack=<id>                      # 免 X-Token（只读语义，与 /api/packs 一致）
  200  application/zip
       Content-Disposition: attachment; filename*=UTF-8''<percent-encoded name>.zip
       Content-Length: <字节数>
       Cache-Control: no-store
  400  {"error": "缺少 pack 参数"}
  404  {"error": "词库不存在或名字不合法"}
  409  {"error": "该词库正在构建/改名，请稍后再试"}
```

- 包名解析**必须**走 `webgen.resolve_pack_id()`（`webgen.py:864`），不许手工拼 `packs/<id>`（越界防护）。
- 不加进 `serve.py` 的 `WRITE_ROUTES`（`:55-56`）。

### 4.4 实现要点

1. `webgen.export_pack(pack_id) -> bytes`（或 `zip_into(pack_id, fp)`）：
   - 用 `zipfile.ZipFile(fp, "w", ZIP_DEFLATED)`；
   - 归档内路径 = 相对包目录（`index.html`、`pack_data.json`、`audio/p001_001.mp3`）；
   - **跳过**任何以 `_` 开头的文件/目录——探针会在包目录里留下 `_inj.html` / `_trace.js`，不能混进交付物；
   - **不许**跨目录读取（只 walk 该包目录）。
2. 并发：导出与「构建 / 改名 / 删除」共用 `_target_lock`，用 `acquire(blocking=False)`；拿不到就 409（与现有写操作一致，不阻塞 HTTP 线程）。
3. 体积与内存：实测《初中英语词汇表》420 个文件 16.75 MB → zip **10.67 MB**，耗时 8.1 s。本期按**内存构建**实现即可，但加一条守卫：包目录 > 200 MB 时改流式（写 `work/_export/<id>.<ts>.zip` 后分块下发并删除）。
4. 归档内文件名全是 ASCII（`index.html` / `audio/pXXX.mp3`），**中文只出现在下载文件名上** → 只需 RFC 5987，不需要 `zipfile` 的 UTF-8 标志。这点与旧文档 §8.1 的判断不同，已实测。
5. 实测压缩率 61~63%（单个整页 mp3 也有 60%），**旧文档"预期 <2%"是错的**；这提升了本功能的性价比，但**不作为承诺**写进 UI 文案（不同码率结果会变）。

### 4.5 边界与失败模式

| 场景 | 期望 |
|---|---|
| 包名带 `..` / `/` / 绝对路径 | 404（`resolve_pack_id` 拦） |
| 包目录存在但没有 `pack_data.json` | 仍然打包（它就是个目录），但日志记一条 `warn` |
| 打包中途磁盘满 | 500 + JSON error；不落半截临时文件（`try/finally` 清理） |
| 同时点两次 | 第二次走同一把锁 → 409 或复用上一次的字节（§4.4 第 3 条的缓存可省掉重复 8 秒） |

### 4.6 验收标准

- [ ] 工作台卡片操作区从「2 链接」变「3 链接」，`_cdp_home.py` 同步改为 3（**接入当天门禁会主动失败，这是设计**）
- [ ] 点下载得到 zip；解压后 `index.html` + `pack_data.json` + `audio/*.mp3` 与源目录**文件数一致**
- [ ] 抽样 3 个 mp3 的 SHA-256 与源文件一致（不对全部 400+ 个做，控制门禁时长）
- [ ] zip 里**没有** `_` 开头的条目（专门造一个 `_trace.js` 再导出验证）
- [ ] 构建进行中导出 → 409 且不产生半截文件
- [ ] 移动端视口下按钮可见可点
- [ ] `python -X utf8 _api_probe.py` 增加：缺参数 400 / 越界 404 / 构建中 409

## 5. 功能 B · 校对表「插一行」

### 5.1 用户故事

> 解析出 57 条，但第 12 条后面明显少了一个词（原书那行被并进了上一行）。我不想整页重新解析，只想在这里补一行。

### 5.2 交互

| 元素 | 行为 |
|---|---|
| 入口 | 每个页/组的表头右侧 `＋ 加一行`（不放进 44px 的行尾列，避免挤压） |
| 插入位置 | 该组**末尾**（最简单、最不容易插错位置）；不做"插入到某行之后" |
| 插入后 | 立刻渲染该行并**聚焦英文输入框**；该行标 `dirty`（已改）|
| 初始值 | `en: ""`、`cn: ""`、`score: 0`、`dirty: true` |
| 折叠中 | 若该组处于折叠状态，插入后自动展开并滚到新行（否则用户看不到自己刚加的行，等于没反馈） |
| 计数 | 词数 / 已改数 / 可疑数实时 +1（走现有 `refreshCounters()`） |

### 5.3 必须有的一条新规则：不许静默丢半空行

现状 `collectRows()` 是 `if (en && cn) push(...)` —— **只填了英文的行会被无声丢掉**。这与项目一贯的"不许静默删用户内容"（AGENTS §6，网页解析带 `--keep-low` 就是为这个）冲突，插一行之后会变成高频踩坑点。

本期规则：

| 行状态 | 提交时 |
|---|---|
| `en` 与 `cn` 都空 | 视为"用户删掉了这条"，跳过（不报错） |
| 只有一边为空 | **阻断提交**，toast「第 N 页第 M 行缺少中文/英文」，并把该行滚动到可见、聚焦空的那个格子 |
| 两边都有 | 正常提交 |

### 5.4 实现要点

- 模型不变，只加一行对象：`S.groups[gi].pairs.push({en:'', cn:'', score:0, dirty:true})`，然后 `fillBody(gi, wrap)` + `refreshCounters()`。
- `isSusp()` 会把空行判成"可疑"（`reasonsOf` 里有低分规则）→ **空 en 的行不参与可疑统计**（否则刚插的行立刻显示红色可疑，误导）。
- 提交前校验放在 `doBuild()` 里、`collectRows()` 之前，**不要**在 `collectRows()` 里偷偷过滤。
- 与 D（重复页检测）的关系：插行会让该页词条集合变化，D 的比较用**提交时的 rows**，所以插行不需要额外通知。

### 5.5 验收标准

- [ ] 插入行后计数与「已改」徽标立即变化
- [ ] 折叠状态的组插入后自动展开并聚焦
- [ ] 只填英文 → 提交被阻断，提示到具体行，**不生成包**
- [ ] 填全 → 提交成功，包内该页词数 +1，且该词在包里可点播
- [ ] `_e2e_generate.py` 增步骤：插一行 → 填词 → 生成 → 在包里断言该词存在
- [ ] 「只看可疑」「只看已改」筛选下，新插入行都可见

## 6. 功能 C · OCR（jpg / 扫描件）

> **引擎已定：RapidOCR（ONNX 推理，模型随 wheel 自带）。** 依据是 2026-11-27 的 Windows OCR spike（`SPIKE_WindowsOCR_20261127.md`）：本机 `en-US` / `en-GB` 均 `NOSUPPORT`，只能用中文模型认英文 → 英文召回 50%、`borrow` / `return` 整行丢失；且 Windows OCR 依赖**目标机器**的语言包，便携包带不走。
>
> 技术细节（依赖版本、列归并算法、便携包改造、门禁、任务分解）见 `OCR_RapidOCR_实施计划_v1_20261127.md`；本节只写**产品要求与验收**。

### 6.1 已定案：选 ② RapidOCR（下表保留作决策证据）

> **2026-11-27 决策**：选 ②。理由只有一条硬的——**它是唯一能随便携包自包含交付的**（① 依赖目标机语言包）。体积代价 +170~200 MB 已确认接受。

| 方案 | 依赖 | 便携包增量 | 中英混排 | 主要风险 |
|---|---|---|---|---|
| **① Windows 内置 OCR**（`Windows.Media.Ocr`） | 无 pip 大包 | ≈0 MB | **本机只有 zh-cn / ja / es-es，无 en** | 依赖目标机语言包 → **无法随包交付（决定性）**；实测英文召回 50%；拿不到置信度 |
| **② RapidOCR（onnxruntime）** ← 已选 | `rapidocr==3.10.0` + `onnxruntime`（**模型随 wheel 自带**） | **+170~200 MB** | 好（PP-OCRv6 模型） | 便携包变大；`build_dist.ps1` 的 `$pkgs` 要加 10 项；首启 1~3 s |
| ③ Tesseract | 外部 exe + `chi_sim`/`eng` 语言包 | +100 MB 以上 | 表格/混排弱 | 部署最麻烦，不推荐 |

**落选理由（已归档，不再讨论）**：

- **① Windows 内置**：实测英文召回 50%、模糊 73%、`borrow` / `return` 整行丢失；且依赖目标机语言包 —— 即便给它装 en-US 也只能解决"本机能用"，解决不了交付。
- **③ Tesseract**：要外部 exe + `chi_sim`/`eng` 语言包，表格与中英混排最弱，部署最麻烦。

### 6.2 输入

- 新格式：`.jpg` / `.jpeg` / `.png`，走 `MAGIC` 表新增魔数（`\xFF\xD8\xFF` / `\x89PNG`），延续"按魔数不按扩展名"的现有做法（`webgen.py:59`）。
- 单文件上限沿用 20 MB（手机原图通常 2–8 MB）。
- **一张图 = 一个 doc = 一页**。多页扫描件：分别上传，生成时用「并入」串起来（页号自动 offset）。本期不改 job 模型。
- 扫描 PDF（有页面但 `get_text()` 为空）：本期**先不做自动转 OCR**，只做图片输入，避免"静默变了行为"。列为下一期。

### 6.3 抽取与配对

1. RapidOCR 一定给 bbox（`boxes` / `txts` / `scores`），所以**按列归并**：行聚类（y 带）→ 列聚类（x 间隔）→ 列角色识别（序号 / 英文 / 音标 / 中文）→ 同 y 行内配对。
2. **分不出列怎么办**（书是「英中混排一行」或照片歪斜）：退化为按行内 `en` 与 CJK 正则切分；仍不确定 → 全部标"可疑"并给理由，**不猜配对**（R3）。
   算法细节与容差见实施计划 §5，此处不重复。
3. 去掉行首编号（`12 what` → `what`）与页眉页脚（重复出现在多张图顶/底的行）——本期只做"去掉纯数字行 + 与首行高度接近的重复行"，不做过度的启发式。
4. 音标段（`[ˈæpl]` / `/ˈæpl/`）沿现有规则剥离，不显示（音标已拍板不加）。

### 6.4 与校对表的联动

- OCR 出来的词条一律带 `score`，低分标可疑并给**理由 + 建议**（沿用现有"点行尾 `?`"机制）。
- 由于 OCR 必错，**必须先有 B（插一行）**，否则用户只能重解析。
- 上传卡文案要改：不再只写 `docx / pdf / txt`，加图片；并在选中图片时提示「照片需正对、四角完整、避免阴影，否则识别率会明显下降」。

### 6.5 性能与体积

| 项 | 目标 |
|---|---|
| 单张 A4 照片识别 | ≤ 5 s（不含后续 TTS）；首启另加 1~3 s 模型加载，进度条要提前说话 |
| 便携包增量 | **+170~200 MB**（新增依赖 wheel 合计 111 MB，装后膨胀；release 85 MB → 约 260 MB） |
| 内存 | 峰值 ≤ 300 MB（一张 12MP 图解码约 36 MB，注意别同时留原图+缩放图+二值图三份） |

### 6.6 失败模式（必须在 UI 上说清，不许假装成功）

| 情形 | 期望行为 |
|---|---|
| 一张图一条都没识别出 | 明确报错「没有识别到文字，可能不是词汇表页或分辨率过低」，**不生成空词库** |
| 识别出但无法配对 | 全部进校对表并标可疑，理由如实写 |
| 手写体 / 竖排 / 大幅倾斜 | 允许失败，提示"本期不支持手写与竖排" |
| 图片超过 20 MB | 上传即拒（沿用现有六类拒绝之一） |

### 6.7 验收标准（spike 阶段就按这个判）

## 7. 功能 D · 重复页检测

### 7.1 要解决的问题

现在把同一页并两次，会被词级 `_dup_report` 拦成 409 —— **但那是开跑之后**，用户已经点了生成、等了半分钟。而且 409 的文案是"整批重复"，用户得自己反推是哪一页重复了。

### 7.2 定义

对**每一张勾选的页**（`collectRows()` 之后的 rows，按 page 分组）：

```
本页词集合 P = { _dup_key(en, cn) }              # 与 webgen._dup_key 完全一致：en.strip().casefold() + cn.strip()
目标包每页词集合 Q_j（j = 已有页号）
重合率 r = |P ∩ Q_j| / min(|P|, |Q_j|)
```

判定（只在**并入**模式计算；新建模式没有目标包）：

| 条件 | 等级 | 呈现 |
|---|---|---|
| `r ≥ 0.8` 且 `len(P) ≥ 8` | **高度疑似重复页** | 橙色警告条，列出"本批第 2 页 ≈ 包里第 5 页（82%，18/22）"+ 3 个示例词；生成前需**二次确认** |
| `0.5 ≤ r < 0.8` | 部分重合 | 灰色提示，不阻断、不需确认 |
| `r < 0.5` | 不提示 | — |

### 7.3 为什么不做成"阻断"

- 用户可能**故意**重并某一页去更新（比如改了译文）。
- 真正的硬拦留给词级 `_dup_report`（整批 ≥30% / 边界滑移 / 同页重复 → 409），两层职责清晰：**页级负责"让你知道"，词级负责"不许发生"**。
- 页级若也 409，就会出现"我想更新一页却永远并进去"的死结。

### 7.4 接口与实现

新增只读接口（免 token，与 `/api/packs` 同级）：

```
GET /api/packpages?pack=<id>
  200 {"pack": "<id>", "pages": [{"page": 1, "n": 57, "keys": ["apple\u0000苹果", ...]}, ...]}
  404 {"error": "词库不存在"}
```

- `keys` 由**服务端**用 `webgen._dup_key()` 生成（大小写折叠规则只有一份实现，前端不重写）。
- 后端复用现成的 `_pack_pairs_by_page(pack_dir)`（`webgen.py` 里给 `_dup_report` 用的那个）。
- 前端在 `setStep(3)`（选目标卡）进入时拉一次，本地对勾选页做集合交集；命中阈值就渲染警告条。
- 体积：411 词的包约 15 KB，可接受；> 5000 词时改为只返回 `keys` 的 SHA-1 前缀（本期不做）。

### 7.5 验收标准

- [ ] 造 2 页的临时包：把第 1 页再并一次 → 出现"高度疑似重复页（≥80%）"，且**未点确认时生成按钮不可用**
- [ ] 把第 2 页并进去 → **不出现**警告
- [ ] 书里跨单元同词（look / work 那种零星重复）→ 不触发页级警告（重合率低），且词级仍走"放行 + `dup_warnings`"
- [ ] 新建模式（无目标包）→ 不请求 `/api/packpages`、不显示警告
- [ ] `_api_probe.py` 增：`/api/packpages` 缺参数 400、越界 404、返回的 `keys` 与 `_dup_key` 结果一致
